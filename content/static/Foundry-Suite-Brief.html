Foundry-Suite Brief

What it is

Foundry-Suite is a local-first, federated set of tools and conventions for doing knowledge work with AI beside you.

It is designed around a simple idea:

  • Artifacts are the unit of progress.

Instead of chats disappearing into history, Foundry-Suite emphasizes producing concrete outputs you can review, version, share, and reuse.

What it’s for

If you regularly do any of the following, Foundry-Suite is meant to help:

  • Turn messy inputs into durable outputs
  • Move from idea to execution without losing context
  • Keep provenance, evidence, and decisions attached to the work
  • Federate work across multiple tools and repositories

The operating principles

Principle What it means Why it matters
Artifact-first Write things down as deliverables Produces shareable progress
Human-in-the-loop You stay the editor and approver Prevents silent automation failures
Provenance-first Attach sources, inputs, and rationale Enables trust and auditability
Federation over monolith Compose small tools via interfaces Keeps the system adaptable
Local-first by default Keep the workshop close to you Reduces friction and fragility

The lifecycle spine

Foundry-Suite aligns tools around a repeatable lifecycle for knowledge work:

  1. Learn: gather context, sources, notes
  2. Ideate: shape possibilities and options
  3. Intent: decide what to build and how
  4. Build: implement and package outputs
  5. Publish: distribute artifacts to the right places

What’s inside

Foundry-Suite is intentionally modular. A “foundry” is a focused workshop for one stage of work.

Examples of workshops and supporting capabilities:

  • Idea capture and refinement
  • Intent specification and traceable execution
  • Comms publishing pipelines
  • Registries and conventions
  • MCP-connected tooling for automation and integration

What makes the outputs different

Foundry-Suite aims to make outputs:

  • Readable by humans (clean structure, skimmable summaries)
  • Executable by tools (frontmatter/config as contracts)
  • Reviewable (guardrails, safety latches, explicit approvals)
  • Portable (single-file HTML artifacts where helpful)

A quick tour

Start with these concepts:

  • A suite is not a single app. It’s a set of interoperable workshops.
  • Governance matters. Naming, schemas, and publishing rules are part of the product.
  • Interfaces come first. Tools should compose without tight coupling.
